# Ideation (아이디어 탐구)

사용자의 탐구적 질문이나 막연한 아이디어를 분석하고, **구체적인 실행 가능한 방향**으로 발전시키세요.

## 언제 사용하는가

- "~하려면 어떻게 해야 할까?"
- "~를 개선하고 싶은데..."
- "~같은 걸 만들 수 있을까?"
- 구체적 요구사항이 아닌 탐색적 질문

## 필수 수행 사항

### 1. 문제/기회 정의
- 사용자가 **진짜로** 해결하려는 문제는 무엇인가?
- 현재 상태와 원하는 상태의 gap은?
- 왜 이것이 중요한가? (동기, 맥락)

### 2. 가능한 접근법 탐색
- 최소 3가지 이상의 접근법을 제시
- 각 접근법에 대해:
  - 핵심 아이디어
  - 장점
  - 단점/리스크
  - 필요한 노력 수준 (low/medium/high)

### 3. 연구 및 조사
- 관련 기존 코드/시스템 탐색
- 유사한 문제의 일반적 해결 패턴
- 제약 조건 파악 (기술적, 시간적, 리소스)

### 4. 방향 제안
- 추천하는 접근법과 그 이유
- 대안이 있다면 사용자에게 선택지 제시
- spec 단계로 넘길 수 있는 구체화된 문장 제안

## 좋은 ideation output 예시

```markdown
## 문제 정의
사용자가 원하는 것: 시간이 지날수록 코드베이스를 더 잘 이해하는 워크플로우
핵심 니즈: 지식의 축적과 재사용

## 가능한 접근법

### A. Knowledge Base 시스템
- 핵심: 학습 내용을 구조화된 문서로 저장
- 장점: 명시적, 검색 가능, 버전 관리 가능
- 단점: 수동 관리 필요, 문서가 outdated 될 수 있음
- 노력: Medium

### B. 자동 요약 시스템
- 핵심: 세션마다 학습 내용을 자동 추출/저장
- 장점: 자동화, 일관성
- 단점: 정확도 이슈, 노이즈
- 노력: High

### C. 점진적 CLAUDE.md 강화
- 핵심: 기존 CLAUDE.md에 발견사항을 점진적 추가
- 장점: 간단, 즉시 적용 가능
- 단점: 구조화 어려움, 파일이 비대해질 수 있음
- 노력: Low

## 추천
접근법 C로 시작하여, 필요시 A로 확장하는 것을 권장합니다.

## Spec으로 넘길 요청
"CLAUDE.md에 학습 내용을 자동 추가하는 post-session hook 구현"
```

## 금지 사항

- 하나의 접근법만 제시하고 끝내기
- 코드 작성 (implement 단계에서)
- 세부 구현 설계 (design 단계에서)
- 사용자의 아이디어를 무조건 수용 (비판적 분석 필요)

## 완료 조건

- [ ] 문제/기회가 명확히 정의됨
- [ ] 최소 3개의 접근법이 제시됨
- [ ] 각 접근법의 장단점이 분석됨
- [ ] 추천 방향이 근거와 함께 제시됨
- [ ] spec 단계로 넘길 구체화된 요청이 준비됨
